# JARVIS v1 End-to-End Matrix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the v1 A–N test matrix reviewable, deterministic and green on Windows/PGlite, Windows/PostgreSQL, Linux/PGlite and Linux/PostgreSQL without duplicating the existing harness.

**Architecture:** Keep `tests/e2e/harness.ts` as the only Core composition seam and inject only executors or fake HTTP/stdio services. Put reviewable generated inputs in `tests/e2e/matrix/*.cases.json`; table-driven tests consume those files and assert persisted tasks, events, actions, audits and observations. Hardware, credentials and packaged-app checks remain explicit opt-in suites and never count as fixture evidence.

**Tech Stack:** TypeScript 7, Vitest 5, fast-check, Playwright Electron, Python 3.12 unittest, PGlite, PostgreSQL 18.3, GitHub Actions.

**Spec:** `docs/release/v1/PROGRESS.md` plus the operator-provided “JARVIS v1.0.0 release prompt”, Phase 1 §§5.1–5.3.

## Global Constraints

- Keep coverage floors at lines 95, statements 93, functions 92 and branches 84.
- Tests use PGlite or disposable PostgreSQL schemas; never ports 2160/55432 or the operator's real data.
- Generated secrets only; no transcript, memory, OAuth or credential values in cases or artifacts.
- No new harness, dependency or test skip. Electron remains sequential (`workers: 1`).
- Every case asserts Core records; fixture evidence is labelled **tested only**.
- Portable Node `.tools/node-v24.22.0-win-x64` and locked Python environments are authoritative locally.

## Review Focus

- Cancellation while a retry-safe executor is in flight must end `CANCELLED`, never `RECOVERY_REQUIRED`; pin this in the PostgreSQL E2E matrix.
- An action denied after plan admission must not dispatch and must leave auditable records.
- HIGH `ask` requires both the plan hash and a separate single-use action approval on every entry path.
- Restart must rebuild budgets, circuits, permissions, plans, brain state and outbox state from records without replaying uncertain work.
- Every opt-in suite must report why it skipped and must not be represented as passed when hardware or credentials are absent.
